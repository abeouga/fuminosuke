# テンプレートパッケージ運用ガイド

## 1. `.llmocr-template`とは

`.llmocr-template`は、1つのOCRテンプレートを別のPCへ移すための自己完結型ファイルです。読み取り矩形、項目割当て、書類判別条件、書類名規則、候補値、出力レイアウト、必要な画像、対応する場合は元XLSXをまとめて保持します。

OCR済み書類、OCR履歴、APIキー、Google認証情報、Google DriveのファイルID、PC固有の保存先は含みません。システム全体を復旧するバックアップではありません。

## 2. 書き出す

1. 「読み取り」を開きます。
2. 対象テンプレートの「配布用に書き出す」を押します。
3. publisher ID、package ID、versionを確認します。
4. inspectionに表示された内容、除外情報、警告を確認します。
5. 「ファイルに保存」または「Google Driveへ正式版として保存」を選びます。

正式版は同じpublisher ID、package ID、versionで内容を差し替えられません。修正した場合はversionを上げて新しい正式版を作成します。

## 3. 取り込む

1. 「読み取り」の「テンプレートを取り込む」を押します。
2. PC上の`.llmocr-template`を選ぶか、Google Driveの一覧を取得します。
3. 「内容を確認」を押し、テンプレート名、version、candidate、asset、互換性、競合状態を確認します。
4. 「有効化せず取り込む」を押します。

取り込みだけでは、現在使っているテンプレートは切り替わりません。取り込み後に内容を確認し、使用する場合だけ「有効版にする」を押します。

## 4. 有効化

有効化すると、そのversionの読み取り矩形、field、candidate、書類判別、書類名、出力レイアウトが実行時に使用されます。既存の有効版が確認後に変更されていた場合は競合で停止します。一覧を更新し、どちらを有効にするか確認してから再実行してください。

同じversionをもう一度有効化しても重複は作られません。取り込みや有効化が途中で失敗した場合は、自動で一部だけ残さず、inspectionからやり直します。

## 5. Google Drive正式版と作業版

正式版は配布・再利用する固定版です。同じidentity/versionの内容は変更できません。誤りを直す場合はversionを上げます。

作業版は編集途中の同期用です。同じdraftを更新できますが、別PCまたはDrive側で先に更新されている場合は競合します。競合時は上書きせず、最新の作業版を再取得し、差分を確認してから新しいrevisionとして保存します。

正式版と作業版は用途が異なります。作業版を正式版の代わりに配布せず、確定した内容は新しい正式版として発行します。

## 6. 「配布者未確認」の意味

現在のpackageには電子署名がありません。publisher IDは記載されていますが、本人が作成したことまでは証明できません。そのため、fileとGoogle Driveのどちらから取得しても`UNVERIFIED`、画面では「配布者未確認」と表示されます。

配布元が不明なpackageは取り込まないでください。既知の配布元でも、inspectionで内容とversionを確認してから取り込みます。

## 7. version競合と上書きされない場合

- 同じidentity/version・同じ内容: 既存の取り込み結果を再利用します。
- 同じidentity/version・異なる内容: 上書きせず、version競合として拒否します。配布元でversionを上げて再Exportします。
- 古いversion: 取り込めますが、自動では有効になりません。必要性を確認して明示的に有効化します。
- 非対応versionまたは機能: アプリを更新するか、対応する旧形式を配布元に依頼します。

競合を避けるためにpackageファイルを手で書き換えないでください。修正元のテンプレートを編集し、新しいversionとしてExportします。

## 8. 別PCで使う

1. 元PCでテンプレートを正式版としてGoogle Driveへ保存するか、`.llmocr-template`ファイルへ保存します。
2. 移行先PCへ同じ静的システムを用意し、必要なGoogle/OpenAI設定をそのPCで行います。認証情報はpackageから移りません。
3. 移行先PCで「テンプレートを取り込む」を開きます。
4. Drive正式版またはfileをinspectionし、「有効化せず取り込む」を実行します。
5. 内容を確認して明示的に有効化します。
6. テスト用書類を1件読み取り、書類判別、書類名、出力先、XLSX/Google Sheetsを確認します。

元PCのDBは不要です。OCR済み書類や履歴も移したい場合は、別途システムバックアップを使用します。

## 9. Drive障害時

Drive一覧取得または保存が失敗した場合、正式版を上書きしたものとして扱いません。通信復旧後に一覧を再取得し、inspectionから再実行します。手元に保存済みの`.llmocr-template`があれば、PCから取り込めます。

作業版の更新失敗後は、同じ画面で連続上書きせず、Driveの最新revisionを再取得してください。正式版の保存結果が不明な場合も、まず一覧を確認し、同じversion・同じdigestが存在するかを確認します。

## 10. システムバックアップとの違い

テンプレートパッケージはテンプレート1件の配布単位です。システムバックアップはDB、OCR済み書類、設定対象データなど、workspace全体の復旧単位です。

Google Drive上でも保存領域、操作画面、同期状態は分離されています。テンプレートを移すためにworkspace backupを使用せず、workspaceを復旧するためにテンプレートパッケージだけを使用しないでください。

## 11. packageに含まれない情報

次は含まれません。

- APIキー、OAuth access/refresh token
- Googleアカウント識別情報
- Drive file/folder ID、Drive version、head revision、ETag
- Spreadsheet ID、owner情報
- PC固有path、ローカルDB ID
- OCR済みdocument、OCR履歴、一時ファイル、cache

これらは移行先PCで設定するか、必要に応じてシステムバックアップで移します。

## 12. 個人情報への注意

candidate値、template画像、元XLSXには個人情報や社内固有情報が含まれる可能性があります。配布前のinspectionでassetとcandidateの内容を確認し、不要な氏名、住所、社員番号、記入済み画像を除去してください。

テンプレート画像は原則として未記入の原本を使用します。記入済み画像をtemplate assetとして配布しないでください。

## 13. 復旧と再inspection

取り込み、有効化、Drive同期が失敗した場合は次の順序で復旧します。

1. エラー区分がsecurity、compatibility、version/draft conflictのどれかを確認します。
2. Driveを使用した場合は一覧を再取得します。fileの場合は配布元の原本を再取得します。
3. packageをもう一度inspectionします。
4. security errorは上限や検証規則を緩めず、配布元で修正して新versionを作ります。
5. version conflictはversionを上げ、draft conflictは最新revisionを基準に差分を確認します。
6. 取り込み後は自動で有効になっていないことを確認し、内容を確認してから明示的に有効化します。
7. テスト書類で読み取りと出力を確認します。
