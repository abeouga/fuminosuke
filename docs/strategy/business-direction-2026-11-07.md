# 文之助を業務向けに寄せる方向性（2026-11-07）

社内の業務改善に使うAIエージェント（複数のドメインや社内データをまとめて扱うもの）とつなぐことを想定して、文之助の位置づけ・大量処理の仕様・データの見せ方を整理したメモ。

## 1. 課題意識（あべのメモ）

- 業務で使うには、個々の機能より、機能のつながり（全体の流れ）が問われる。
- 文之助は祖父母向けに作ったが、実際には使ってもらえなかった。ただし、取るべきデータ（UXの気づき）は取れた。これを元に業務側へ寄せていく。
- 業務改善AIエージェントの観点では、「データをどう取り出し、どう見せるか」に重心を置くべき。OCRシステムという方向性と、AIチャットで取り出す方式は合っている。
- 書類の大量処理の仕様が詰まっていない。たくさんアップロードして並列処理はできるが、それでいいのかが決まっていない。
- 文之助は数字で改善を示せておらず、「便利」で終わっている。実際は、テンプレートで最初に構造化し、AIで補助しつつ人がデータの質を保証する仕組みなので、その後の見せ方が肝になる。そこの仕様（チャットで表示していいのか等）が未定。
- 業務改善AIエージェントは、複数ドメインの知識や社内データを1つのエージェントでまとめて扱う方向。文之助は帳票のOCRの仕様に依存したエージェントなので、ここをどう吸収するかの設計の転換が要る。

## 2. 結論：全部を扱うエージェントにはしない

文之助は「紙やExcelの帳票を、AIが安心して使えるデータに変える入口」と位置づけ直す。業務改善エージェントの仕組みの中で、**帳票ドメインを担う部品**として説明する。

## 3. 設計転換の方向：吸収ではなく接続

- 他のドメイン知識まで取り込むと作る量が膨大になり、そうしたエージェントの劣化版になる。
- 複数ドメインをまとめるエージェントは、元データが汚いと根拠のない答えを返す。現場の点検表・日報・台帳など紙やExcelで残っているデータを、構造化して人が品質を保証した状態で渡せる層は、そういうエージェントにとって必要な部品になる。
- 構想にあるCSV出力・API公開・MCPサーバー化は、この「接続」の設計そのもので、方向性は合っている。

説明の例：

> 文之助自体は帳票に特化しています。ただ、確定済みデータをMCPやAPIで外に出せば、社内データを扱うエージェントが帳票由来のデータも根拠付きで使えるようになります。

## 4. 大量処理の仕様：単位を「ファイル数」から「業務」に変える

「たくさん上げて並列処理」に違和感があるのは、処理の単位がファイルになっているから。業務側に寄せるなら、**人の確認作業が枚数に比例して増えないこと**が肝。

| 段階 | 内容 |
| --- | --- |
| 1. 取込 | 月次の束など、業務の単位でまとめて上げる |
| 2. 振り分け | どのテンプレートの書類かを自動判定する |
| 3. 読取 | 裏で順番に処理し、進捗を表示する（待ち行列にすれば、Lambdaの並列の弱さは体験上ほぼ問題にならない） |
| 4. 確認 | 信頼度の低いセルだけを確認キューに集め、人はそこだけを見る |
| 5. 確定・蓄積 | 確定したデータだけが検索・出力の対象になる |

- 4番が「AIで補助しつつ、人がデータの質を保証する」の具体的な形。
- 祖父母に「確認・修正の意味が伝わりにくかった」のは失敗ではなく、品質保証の工程をどう軽くするかというUXの課題を実地で見つけた、という材料になる。

## 5. データの見せ方：チャットだけにしない

チャットは「探す」には向くが、毎回同じことを聞く用途には向かない。見せ方を3つに分ける。

- **探す**：単発の質問はチャットで答え、元の書類の該当セルを強調表示する（実装済み）。根拠を示せるのは、RAG系のエージェントで一番問われる点なので強み。
- **見る**：繰り返し確認するもの（一覧、集計、時系列）は固定画面にする。
- **渡す**：CSV、API、MCPで他のシステムやエージェントに渡す。

## 6. 「便利」で終わらせないための数字

利用者がいなくても自分で測れる。サンプル書類を数十枚用意して次の4つを出す。

| 指標 | 内容 |
| --- | --- |
| 読取精度 | セル単位の正解率 |
| 要確認率 | 人の確認に回ったセルの割合 |
| 確認時間 | 1枚あたり人が確認にかかった時間 |
| 検索時間 | 台帳から探す場合とチャットで探す場合の比較 |

- 要確認率と確認時間は「人がどれだけ楽になるか」に直結し、業務貢献の話につながる。
- 祖父母から得たのは定性的な声だけなので、定性として扱い、数字は自分で測ったものと分けて示す。

## 7. 次の行動

- 先に「現状 → 転換後」の構成図を1枚作る。上の5段階の流れと、接続先として外部エージェントを描く。
- それで「祖父母で学んだこと → 業務で大事なのは品質保証と接続 → だからこう設計を変える」という話が一本の線になる。
