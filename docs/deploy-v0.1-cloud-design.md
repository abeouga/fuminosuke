# v0.1 クラウド運用の設計ゲート

2026-10-15：本書は当時の比較記録として保持する。現在の採用仕様は[Webベータのフェーズ1仕様](web-beta-phase1-2026-10-15.md)。AWS `abe-deploy-user` / 東京、単一EC2＋SQLite/EBS、Cognito招待制・利用者非公開、削除まで保持、新規クラウドDBを選択した。以下の「未決」「SQLite未確定」「原則破棄」は現行の採用条件ではない。実装・配備は未完了。

作成日: 2026-09-30
状態: 比較・推奨条件。採用決定および実装は未完了。

v0.1はExcelアップロード、テンプレート作成、OCR候補の人間レビュー、確定済みExcel取得を提供する。Google OAuth・Drive/Sheets同期、履歴検索、検索用DBは対象外とする。外部ストレージOAuthの非提供は利用者認証の免除を意味しない。

| 未決事項 | 選択肢と判断条件 | 推奨条件 | 実装ゲート |
| --- | --- | --- | --- |
| デプロイ先・運用主体 | 管理者1名の限定公開 / 複数利用者の共有サービス | 運用主体・想定同時利用数・費用上限を決める | 配備先の設定・infra変更は保留 |
| 利用者認証 | 上流のアクセス制御 / アプリ固有認証 | 公開URLへ無認証で利用者データを置かない | 現Google連携の削除で認証を暗黙解除しない |
| 利用者間分離 | 利用者ごとの独立インスタンス / tenant IDによる共有基盤 | 全API・job・artifact・テンプレートの所有権を同じ境界で検証する | tenant方式が未決なら共有DB化を始めない |
| テンプレート保存・共有 | 利用者専有 / 明示共有 | 版と所有原本・mapping・artifactの不変bindingを保持する | 共有単位・所有権・更新権限を決定する |
| Excel・画像・出力保持 | ダウンロード後削除 / 有効期限付き保持 | OCR業務データは原則破棄し、削除時点と再取得猶予を明示する | 数値の保持期間は未決。削除処理を追加しない |
| job復旧 | 再入力を要求 / 一定期間snapshotを保持して復旧 | 受付snapshot・入力・attempt・revisionを同時に保持し、部分削除しない | 処理中・失敗・確定後の期間を決定する |
| DB・job・ファイル基盤 | 限定単独構成 / 共有DB・独立worker・object storage | 所有権・復旧・同時実行条件から選ぶ。OCR検索用RDS/OpenSearchは追加しない | SQLiteを本番共有DBとして確定しない |

現在はSQLite、ローカルdataディレクトリ、FastAPIプロセス内job実行を利用している。この構成で複数利用者間分離・再起動時復旧・クラウド運用を満たしたという証拠はない。

このフェーズの完了は未決事項の可視化であり、採用承認や本番配備ではない。未決事項に依存しないUI修正と既存契約を維持するコード整理を次フェーズで進める。
