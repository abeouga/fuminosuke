## 2. モデルに見せる設定結果

入力を「目的」「元の証拠」「候補の設定結果」「必要な回答」の順にします。候補には正解の順位や推奨マークを付けません。候補の説明は発行済みplanの決定的な投影であり、別のLLM呼出しで生成しません。

| 要素 | 示す内容 | 保持する境界 |
| --- | --- | --- |
| 証拠 | 元の画像2枚、cell ref・印字・座標・権限、gridの全行全列 | 文字の推測修復、crop変更、範囲外の書込をしない |
| 構造 | どの欄を見出し・個別項目・繰り返し表にするか | 全候補を同じ基準で説明し、候補を増減しない |
| form | 各行のラベル→入力欄、親と読取方式の質問先 | 親をnullで確定したと見せず、未選択factorを明示 |
| records | 対象行の順序、列ごとの対象cell、用途別の設定結果 | 全空行・印字済み行も保持。数値の左列を自動でkeyにしない |
| factor | 適用するunit・列・cell集合、各選択肢の効果 | 別構造・別列のchoiceを混在させない |
| name | 表題か値の名前か、設定先unit/slot、根拠refと制限 | 同じusageの名前が複数でも所属を曖昧にしない |
| 保留 | 文脈不足、適合候補なしの別選択肢 | unknownをignoredへ置換しない |

## 3. 保留と採用の分離

### Responses

新指示文で「空欄は設定不能の理由ではない」と明確にします。structureの`needs_context`と`none_of_these`、必須nameのnullは引き続き保留です。schemaに自由作文、自己confidence、追加のreasonを増やしません。後段で保留を正答候補へ置き換える補修も行いません。

モデルが返した保留理由とサーバーが検知した失敗を分けて記録します。`needs_context`はモデルの申告であり、実際に画像が欠けたと断定しません。unsupported、policy拒否、schema違反、現在性失効、通信エラーも同じ「根拠不足」にまとめません。

### Decisions

候補選択の質問名は現行のcomponent aliasを保ち、固定された同じ証拠を対象とするpredicate `context:<component>`を一問加える案を比較します。質問名の変更を比較へ混ぜません。

> この所有範囲について、候補同士の用途の違いを区別するのに必要な周辺の見出し・欄の関係・凡例・利用上の説明が、提示された証拠内に十分ありますか。記入値が空であることや候補が存在することだけでは判断しないでください。適切な候補がないことと、文脈が不足することを区別してください。

これは選択済み候補の正しさを尋ねる質問ではありません。先の回答を入力として使わず、要求前に全文を固定するため同じ要求で送れます。両回答は同じモデル・証拠から出るため、誤りが独立であるとは仮定しません。predicateの確率を正しさの証明やchoiceのconfidenceの代用品にしません。公式仕様は独立した質問の同梱、依存する判断の別要求、confidenceと確率分布の区別、用途に合ったラベルによる校正を説明しています。[OpenAI Decisions](https://developers.openai.com/api/docs/guides/decisions)

質問数はready component数の2倍、既存64問上限を維持します。超過時は送信前保留です。上限のために一部componentを黙って捨てません。元のrouteは維持し、generated nameまたは条件付きfactorを持つ要求はResponses一回、独立した有限選択だけDecisions一回です。失敗後の自動fallback・retry・並列先行送信は0です。

採用規則は、まず質問名・型・choice・全確率・範囲・モデルを検証し、その後に校正済みpolicyを評価します。boolを数値として受け入れず、有限な0〜1だけを使い、choice分布の合計許容差は既存の0.00001を維持します。predicateにはconfidenceを要求しません。欠落・重複・不正値・第一候補と異なるchoiceは要求全体を拒否します。有効なrefusal、合法なsentinel、同率第一候補はそのcomponentを保留し、依存closureも保留します。正当な別componentまで不必要に破棄しませんが、意味の合格判定はscope全体で行います。

規則候補は次の5個だけです。P0は現行の対照、P1〜P4は未採用の校正対象です。正解を見て新しい数値やcase例外を追加しません。`margin>0`を全規則に要求して同率第一候補は通しません。

| 方針 | context probability下限 | confidence下限 | top二候補のmargin下限 |
| --- | ---: | ---: | ---: |
| P0 現行対照 | 使用しない | 0.90 | 0.15 |
| P1 | 0.97 | 0.90 | 0.15 |
| P2 | 0.97 | 0.50 | 0.10 |
| P3 | 0.97 | 0.00 | 0.00、かつ厳密に正 |
| P4 | 0.90 | 0.50 | 0.10 |

P3を含める目的は「十分な文脈と正しい第一候補があるのにconfidenceだけで落ちる」という仮説の検証です。confidenceを無視する方式を製品へ先に採用する意味ではありません。context判定もE12型の誤答を通すなら、この設計は不合格です。共通compilerは物理・所有を保護しますが、意味上の正答を保証しません。

## 6. データ分割と保留負例

T1〜H2、E01〜E12、旧校正12範囲は開発用へ固定します。旧校正が未送信であることを最終評価の独立性と読み替えません。新規校正12と評価18は元帳票family単位で分離します。同じ帳票の文字・色・座標だけを変えた派生は同じfamilyです。内容SHAだけでなく出典と派生元で分割を検査します。
