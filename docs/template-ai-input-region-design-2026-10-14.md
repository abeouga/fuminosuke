## 2. 採用する責務分割

```text
不変の原画像・編集snapshot
  → 領域planner（所有範囲・依存・呼出し上限）
  → 原位置画像 + 入力先別catalog
  → Lunaの完成応答（領域内のgeometryと独立した意味）
  → 既存geometry/意味compiler・共通prepareで検証
  → 不変の領域案を公開 → 画面で「案を反映」
  → 累積反映receiptと手動変更を照合 → 共通authoring保存
```

新設する責務は領域計画、領域契約、累積案の照合に限定する。別の保存系、OCR系、独自mapping生成器は作らない。既存の規則的な表の圧縮経路は、同じ入力先検証と公開単位へ接続して維持する。

比較した方式：全ページのprompt修正だけでは全体完了待ちが残る。セルごとに1要求では接続・凡例の文脈と予算効率が悪い。役割判定→意味付けの2段AI直列処理は最初の応答を遅らせる。今回は**文脈を保った領域を1要求で処理**する。確信がない領域は未解決とし、無制限の再質問・別モデルへの隠れたfallbackは行わない。

## 3. 入力と回答の新契約

新規解析に `template-analysis.region-plan.v1`、`region-pack.v1`、`region-answer.v1`、公開/反映HTTP契約 `template-analysis.v3` を導入する。旧保存テンプレートや旧OCR jobを変換しない。旧版の実行途中の解析・復旧journalは明示失効し、手動下書きを保持して再解析を案内する。旧proposalを新契約として解釈しない。

### 入力

- server発行のsnapshot/plan/region/catalog digest、page identity、原画像SHA、canonical座標系。
- `ownedRefs` と各refの**元の完全なgeometry**、`writeBounds`（未検出領域も含む）、`contextRefs`、保護facet。
- 入力候補ごとの `inputRef → allowedLabelRefs/axis`。距離・検出role・textHintはいずれも未検証の補助情報。双方向候補があり得ることを明示する。
- 領域とその周囲64pxの原位置画像、高解像度の必要文脈。全体の縮小画像は位置把握用に1枚。refs付き画像には番号を実印字と区別して配置する。個別セルを並べ直すatlasと全ページの巨大なb候補表は送らない。
- 凡例・共通見出しは印字領域を原位置で追加cropし、参照を読み取り専用にする。画像に含めても書込権限は増えない。
- 画像やmetadataのhashキャッシュは原画像・draft・保護状態に束縛。正解gold、過去の正しい回答は本番要求に入れない。

### 回答

geometryは既存の閉じたadd/resize/split/merge/remove_duplicate操作を再利用する。新規n参照は領域内の一時参照であり、正規IDやtargetPathではない。

各意味欄は `input`（c/n）、`name`、`labels`、`axis`、`reading` を明示する。見出しなしの場合は現行の具体的根拠を必須にする。b参照を経由して入力先を推測する回答形式は新経路から廃止する。共通resolverがinputの所有権、変更後geometry、許された接続、保護、重複を再検証する。

回答の例示形は `field(input=c15, labels=[c14], reading=symbol)`。見出しc14をinputにした回答も形式上は成立し得るため、これだけで意味誤認を防げるとは扱わない。画像とgoldの品質判定を別に行う。

- 独立した自由記入・チェック・数値・日付を一つのfree textにまとめない。
- 印刷選択肢は既存markSets/読取設定へ変換し、各選択肢の値が独立して保存・復元できることを要求する。共有cropを使う場合も、自由記入値を同じ選択肢値へ吸収しない。
- 日付は既存の複合値機構と必要な年/月/日・元号の範囲を保持する。未対応型を文字列へ黙って格下げしない。
- 同じ領域のgeometryと、それに依存する全ての意味は一括検証・一括反映する。片方のみの成功は公開しない。
- `unresolved` はセル参照に加え、未検出位置のbboxと理由を表せる。境界をまたぐ新規欄は `cross_region` とする。未宣言refはserver側でも未解決にする。モデルの「全て見た」を完成判定にしない。
- 受付・出納印など機能未対応の領域は `manual_required` として可視化し、架空の自動読取項目にしない。

## 4. 領域計画と依存

### 分割規則

1. ページ全域の矩形を再帰的に分割する。既存セルの端を候補とし、セル数の偏りが最小の境界、同点はaxis/座標で決定する。目安24セル、最大16領域/ページ。空白を除外せず分割領域の合計がページ全域を覆う。
2. 境界付近2pxは**分割候補を探すヒントのみ**。セル座標は丸めず変更しない。各既存セルは中心で一つの所有領域へ割り当て、その完全なgeometryを所有する。1〜2pxの既存境界重なりは保持する。
3. 新規addは自領域のwriteBounds内で、他領域の既存セル・保護領域との衝突検査も通す。既存枠のsplitは所有する元枠内に限定する。resize/mergeの出力はwriteBoundsと自分の既存footprintの和集合内、他所有セルへの新たな侵入は拒否する。分割ヒントの2pxをgeometry検証の許容緩和に使わない。
4. 保存済みrelation、結合、同じrecord section、可変の共通親をまたぐ書込みは不可。事前に所有領域を統合し、依存閉包を一つにする。固定の外部見出し・凡例はread dependencyとし、対象facetが変わったらその領域案を失効させる。
5. 領域間の読み取り依存はDAGとして保存する。同時に書き換え得る親/見出しを互いに参照する循環は統合する。単に隣接しているだけではページ全体を結合しない。
6. 規則的な表は既存の検証済みgrid検出を通る場合だけ一つの圧縮単位にする。非規則的な表を小さな別表へ自動分断しない。保存済み表の全行列・row keyが依存上分離できなければ表全体を一単位として扱う。
7. 目安を超える依存単位は大きいまま処理し、速度未達を隠さない。既存安全上限を超える場合は保留。16領域を超える場合は未送信分を保留表示し、全体合格にはしない。
8. 未検出欄が分割境界をまたぐ場合、切った片側だけを新規値にしない。隣接領域の再統合案を提示し、後続の明示再解析で処理する。その初回欠落は品質評価で未解決として残す。自動的な追加APIは使用しない。

## 5. 解析中の反映と保存

全体physicalDigest一致の検査を削除するだけの変更は禁止する。新しい反映要求は `regionId/proposalDigest/parentMergeId/requestId/inputDraftDigest` を持つ。

1. serverは受付draftを起点に、発行済みの親merge receiptの直線的な履歴を再構成する。同一領域の二重適用を拒否する。別run・別ownerのreceiptや飛び越し、履歴forkは拒否する。
2. 前回server出力と今回draftの全physicalを照合する。正当な既適用AI操作分だけを基準へ組み込む。未申告のgeometry差分は全未適用案を失効させる。手動geometryは当面全体失効という保守的境界を維持し、局所再baseは実装しない。
3. 意味facetは現行readSetとmanual touchを照合する。同値の手動変更も保護する。無関係な手動意味変更は保持できるが、そのfacetを読む領域は競合にする。
4. 選択した未適用領域のみを現draftへ共通compose/prepareで検証する。依存先の変更、削除、新規枠の衝突、保護違反は全領域単位で拒否する。別の成功領域へ不正な部分を移さない。
5. receiptは入力/出力digest・適用領域・一時ID置換・変更facetを保持する。応答消失時の同一request再送は同じreceiptを返す。履歴は解析run内の案反映だけの記録であり、業務保存を代用しない。
6. frontendは反映中の手動serial変化を検知して旧応答で上書きしない。保留した応答と入力を復旧可能にする。undoは末尾receiptの取消しとして扱い、復旧不能な分岐は案を失効させる。
7. 「確認して保存」は既存authoring保存を使用し、現在のrevisionとanalysis receiptを照合する。保存後はrunを閉じ、未反映案を古いsnapshotとして失効させる。解析中に保存した場合も同じ。後着provider応答を保存済み版へ適用しない。

解析中も検証済み領域の「案を反映」を有効にする。枠のプレビュー、反映済み、未解決、未解析を区別し、全ページが終わったように表示しない。既存AIフォーカス・複数セル枠・スクロールの経路を使い、別の演出システムは増やさない。

- 領域品質とページ全体品質を別々に報告する。最初の一項目だけ正しい回答では先頭領域の合格にしない。

### 5秒の計測

`performance.now()`で「AI解析」操作から、**事前指定した先頭領域の正しい案が描画され、その領域の案反映操作が利用可能になった時刻**まで。領域内の期待機能を全て満たすことを採点後に確認する。ボタン有効化だけでなく実際の反映要求の成功で操作可能性を検証する。反映そのものにかかった時間は別記する。

クリック、文脈取得、snapshot/画像準備、予約待ち、provider開始/初回token/完了、検証、イベント到着、React commit後の描画フレーム、反映、保存を別々に記録する。準備時間はクリック後分を5秒に含む。事前準備がある場合はその時間とcold/warmを併記し、隠さない。

G3の12回すべてで正しい先頭領域が5秒以内、G2でも全5ページの先頭領域が5秒以内を条件とする。最大・中央値・全試行値を示すが、安定したp95とは主張しない。全ページ完了時間・呼出し数・総tokens・修正/保存時間も示す。全体待ち時間を領域分割で悪化させていないかを別に評価する。

実ブラウザー・専用backend/DB・実Lunaを使う。保存response replayは競合検証用であり速度合格の証拠にしない。起動制約が残る場合は準備済みの専用起動手順を提示し、利用者の操作を待つ。起動拒否を別経路で迂回しない。マイク試験はこの評価には含めない。
