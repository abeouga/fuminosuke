# 構造Excel・スキャナー連携型OCR計画

## 1. 概要

本計画では、実書類の画像から表構造を推定してテンプレートを作成する従来方式に加え、帳票の元となるExcelまたはスプレッドシートのセル構造からテンプレートを作成する経路を追加する。

元シートが持つセル位置、罫線、結合、固定文字、表示形式などを再利用し、画像から表構造を逆算する負荷と誤検出を減らす。そのうえで、システムが生成した標準帳票を印刷し、記入済み書類をスキャナーで取り込み、位置補正、セル単位OCR、確認、Excel出力までを一連の処理として提供する。

```text
元Excel・スプレッドシート
  ↓
セル構造の取得と意味付け
  ↓
テンプレートと標準印刷PDFの生成
  ↓
印刷・手書き記入
  ↓
スキャン
  ↓
位置補正・セル単位OCR
  ↓
確認
  ↓
Excelへの反映
```

## 2. 背景と課題

現行方式では、帳票画像から以下の情報を復元する必要がある。

- 表の罫線とセル境界
- 項目名と記入欄の関係
- 見出しと繰り返し構造
- 行番号・列番号の役割
- 出力先フィールド

しかし、多くの帳票はExcelやスプレッドシート上でセルの集合として作成されている。画像化によって失われた構造をAIで再推定する方式は、元データが存在する場合には二重作業となる。

本計画では、元シートが存在する帳票について構造情報を直接取得し、AIによる推定を補助的な処理へ縮小する。

## 3. 目的

- テンプレート作成時の矩形修正数を削減する
- 罫線、結合セル、繰り返し行・列の誤検出を削減する
- 元シートとOCR結果の出力先を安定して対応付ける
- スキャン後の位置ずれを自動補正する
- 問題のあるセルだけを利用者が確認できるようにする
- 既存の画像・PDFからのテンプレート作成機能を維持する

## 4. 対象範囲

### 4.1 対象

- `.xlsx`ファイルからのテンプレート作成
- シート、印刷範囲、セル、罫線、結合セルの解析
- セルまたはセル範囲への意味付け
- 標準印刷PDFの生成
- スキャン画像の取り込み
- 基準画像との位置合わせ
- セル単位OCR
- 確認後のExcel出力

### 4.2 初期段階では対象外

- Excelと同等の表計算編集機能をシステム内に再実装すること
- Googleスプレッドシートとのリアルタイム同期
- Excelアドインの開発
- すべてのセル意味の完全自動判定
- OCR結果の無確認での自動確定
- Wordの自由配置文書への対応

## 5. テンプレート作成経路

利用者には、テンプレート作成開始時に次の2種類を提示する。

### 5.1 画像・PDFから作成

既存方式を維持する。元Excelが存在しない帳票、外部から提供されたPDF、紙しか残っていない帳票に使用する。

### 5.2 Excel・スプレッドシートから作成

元シートの構造を取得し、セルから矩形候補を生成する。利用者は推定された区分と意味を確認し、不足している情報だけを設定する。

初期実装は`.xlsx`アップロードに限定し、GoogleスプレッドシートはExcel形式でのエクスポートを経由する。

## 6. 利用者向け操作フロー

利用者に見せる操作は、原則として次の4段階に限定する。

1. 元ファイルを登録する
2. システムから標準帳票を印刷する
3. 記入済み帳票をスキャンする
4. 問題のあるセルを確認して出力する

以下の内部情報はシステムが管理し、通常利用者には意識させない。

- セル座標
- 矩形座標
- 印刷倍率
- スキャン解像度
- テンプレートIDとバージョン
- 位置補正方式
- 出力先セル座標
- OCRモデルと前処理方式

## 7. 元シートから取得する情報

### 7.1 直接取得する情報

- ワークシート名
- 使用範囲
- 印刷範囲
- 行高と列幅
- セル座標
- セルの固定文字
- 罫線
- 結合セル
- 表示形式
- 数式
- 入力規則
- 非表示行・列
- 改ページ
- 用紙サイズ、余白、印刷方向、拡大縮小設定

### 7.2 推定候補として利用する情報

- 文字が入ったセルを項目名候補とする
- 結合された固定文字セルを見出し候補とする
- 罫線で囲まれた空セルを記入欄候補とする
- 入力規則のあるセルを選択欄候補とする
- 日付・数値書式をデータ型候補とする
- `1、2、3…`などの連番セルを行・列番号候補とする
- 同じ構造が連続する範囲を繰り返し部分候補とする

推定結果は確定情報として扱わず、テンプレート作成画面で確認可能にする。

## 8. セル区分

テンプレート作成時には、セルまたはセル範囲へ次の区分を設定する。

| 区分 | 用途 |
|---|---|
| 項目名 | 記入内容を説明する固定文字 |
| 見出し | 複数項目や繰り返し部分をまとめる固定文字 |
| 記入欄 | 手書き文字、数値、日付などのOCR対象 |
| 選択欄 | 丸、チェック、塗りつぶしなどの判定対象 |
| 行・列番号 | 繰り返す行または列を識別する番号 |
| 読み取らない | 装飾、余白、説明文などの非対象領域 |

行・列番号は構造識別に使用するが、初期段階ではOCR結果の値フィールドとして出力しない。

## 9. 標準印刷データ

テンプレート確定時に、システムは次の成果物を生成する。

- テンプレート定義
- 基準画像
- 標準印刷PDF
- 元セルと帳票矩形の対応表
- テンプレートバージョン

利用者には原則としてシステム生成PDFから印刷させる。Excelから直接印刷すると、端末やプリンタードライバーによって倍率、余白、改ページが変化し、矩形位置がずれる可能性があるためである。

## 10. スキャン入力

### 10.1 推奨条件

- A4
- 300dpi
- グレースケールまたはカラー
- PDF、PNGまたはJPEG
- フラットベッドまたはADF

### 10.2 入力経路

初期段階では次の方式に対応する。

- スキャン済みファイルのアップロード
- 監視フォルダへのファイル保存

TWAIN、WIA、ネットワークスキャンとの直接連携は後続段階とする。

## 11. 位置補正

スキャナー入力でも位置ずれが発生する可能性があるため、補正処理は省略しない。

```text
入力画像
  ↓
ページ領域検出
  ↓
向き判定
  ↓
傾き補正
  ↓
基準画像との位置合わせ
  ↓
補正後の座標でセルを切り出す
```

### 11.1 主なずれの原因

- 原稿を置いた位置による平行移動
- ADF搬送時の傾き
- 印刷時の拡大・縮小
- 自動切り抜き
- ページ端の欠落
- 紙の曲がりや伸縮

### 11.2 補正基準

- 帳票外枠
- 表の主要な交点
- 固定ラベル
- ページ四隅
- 必要に応じて印刷時に付与する位置合わせマーカー

補正結果が許容値を超えた場合はOCRを自動確定せず、再スキャンまたは確認を要求する。

## 12. OCRと確認

位置補正後、記入欄と選択欄だけを切り出してOCR処理する。

OCR結果は最初にDB上の下書きとして保存する。以下の条件に該当するセルは確認対象とする。

- 信頼度が低い
- 空欄判定が不確実
- 必須項目が空欄
- データ型と認識結果が一致しない
- 同一書類内で値が矛盾する
- 位置補正の誤差が大きい
- テンプレートの想定範囲から文字が外れている

新規テンプレートの初期利用期間は全セルを確認し、修正履歴が蓄積された後に確認範囲を段階的に縮小する。

## 13. Excel出力

確認済みデータだけをExcelへ反映する。

### 13.1 出力方法

- 元Excelのコピーへ値を入力する
- 元セルと出力先セルの対応をテンプレート定義で保持する
- 元ファイルを直接上書きしない
- OCR前画像、OCR結果、確認結果、出力ファイルをジョブ単位で関連付ける

### 13.2 出力失敗時

- 確認済みデータを失わない
- 出力状態を失敗として保存する
- Excel出力だけを再実行できるようにする

## 14. 機能要件

### 14.1 Excelインポート

- `.xlsx`をアップロードできる
- 対象シートを選択できる
- 印刷範囲を確認できる
- 解析できない機能や設定を警告できる
- 元ファイルのハッシュを保存できる

### 14.2 意味付け画面

- セルを単体選択できる
- 複数セルを範囲選択できる
- 行・列単位で一括設定できる
- セル区分を設定できる
- データ型を設定できる
- 繰り返し範囲を設定できる
- 出力先を確認できる
- 未設定セルだけを抽出できる

### 14.3 スキャン処理

- テンプレート候補を判定できる
- ページの向きと傾きを補正できる
- 基準画像へ位置合わせできる
- 補正品質を数値化できる
- セル単位で画像を切り出せる

### 14.4 確認と出力

- OCR結果を下書き保存できる
- 元画像とセル画像を確認できる
- 修正履歴を保存できる
- 確認済み結果だけを出力できる
- 出力失敗を再実行できる

## 15. 非機能要件

- 元Excelを破壊・上書きしない
- テンプレートの変更履歴を保持する
- 同じテンプレートバージョンで結果を再現できる
- OCR、補正、確認、出力の状態を分離して保存する
- 処理失敗時に途中結果を失わない
- APIキーや認証情報を帳票データへ保存しない
- 複数利用者が同じテンプレートを利用しても定義が変化しない

## 16. 段階的実装

### Phase 0: 検証資料の準備

- 公開されているExcel帳票を5種類以上収集する
- 単純表、繰り返し表、選択欄、複数シート、Excel・PDF併用帳票を含める
- 各帳票について期待するセル区分と出力先を手動で定義する

完了条件:

- 検証帳票と期待結果が揃っている
- Excel解析結果を比較できる基準データがある

### Phase 1: Excel構造の取り込み

- `.xlsx`アップロード
- シート選択
- セル、罫線、結合、印刷範囲の解析
- ブラウザ上でのセル構造表示

完了条件:

- 対象シートの表構造が画像解析なしで表示される
- セル座標と表示矩形が対応している

### Phase 2: セルの意味付け

- 区分候補の自動設定
- 単体・複数・行列単位の区分変更
- 繰り返し構造と出力先の設定
- テンプレート定義の保存

完了条件:

- OCR対象セルと非対象セルを明確に分離できる
- 元セルと出力先を一意に対応付けられる

### Phase 3: 標準PDFと位置対応

- 標準印刷PDFの生成
- 基準画像の生成
- 元セルから帳票矩形への座標変換
- テンプレートバージョン管理

完了条件:

- PDF上の各矩形と元Excelセルが対応している
- 同一バージョンから同一の印刷結果を再生成できる

### Phase 4: スキャン位置補正

- スキャン画像アップロード
- ページ検出、傾き補正、位置合わせ
- 補正品質の判定
- 補正後のセル切り出し

完了条件:

- フラットベッドとADFの画像でセル切り出し位置が許容範囲内に収まる
- 補正不能な画像を自動確定しない

### Phase 5: OCR・確認・Excel出力

- セル単位OCR
- DB下書き保存
- 確認画面
- 元Excelのコピーへの書き込み
- 出力再試行

完了条件:

- 確認済み値だけが正しいセルへ出力される
- 失敗後も確認済みデータを保持して再出力できる

### Phase 6: スキャナー連携の自動化

- 監視フォルダ
- TWAINまたはWIA連携の調査
- 複合機からの直接送信
- 複数ページ、両面、連続処理

完了条件:

- スキャン後のファイル選択操作を削減できる
- ジョブとテンプレートを誤って対応付けない

## 17. 評価指標

構造認識と文字認識を分離して評価する。

### 17.1 テンプレート作成

- テンプレート作成時間
- 手動で作成・修正した矩形数
- 区分修正数
- 繰り返し構造の修正数
- 出力先対応の修正数

### 17.2 スキャン位置補正

- セル境界との平均位置誤差
- 切り出し失敗率
- 再スキャン率
- 補正不能率

### 17.3 OCRと確認

- 文字修正率
- 空欄誤判定率
- 誤ったセルへの割り当て率
- 1枚当たりの確認時間
- スキャンからExcel出力までの所要時間

## 18. 主なリスクと対策

| リスク | 対策 |
|---|---|
| 元Excelが存在しない | 既存の画像・PDF経路を維持する |
| Excel上の構造に業務上の意味がない | 意味付け画面で確認する |
| 印刷環境によって倍率が変わる | システム生成PDFを標準とする |
| スキャナーでも位置がずれる | 毎回位置合わせと品質判定を行う |
| 1台のスキャナーに最適化される | フラットベッド、ADF、スマートフォンで検証する |
| 複雑なExcel機能を解析できない | 未対応機能を警告し、対象範囲を段階的に拡張する |
| OCR誤認識がExcelへ確定される | DB下書きと確認工程を必須にする |
| テンプレート変更で過去結果が再現できない | バージョン単位で定義と基準画像を保存する |

## 19. 最終的な製品像

本システムは、すべての帳票を画像からAIで推測するソフトではなく、次のように入力経路を選択する帳票処理基盤とする。

- 元シートが存在する場合は、確定したセル構造を再利用する
- 元シートが存在しない場合は、画像・PDFから構造を復元する
- OCRは手書き内容の読み取りへ集中させる
- 不確実な結果だけを利用者へ提示する
- 確認済みデータを元の表構造へ戻す

内部的には「構造Excel、スキャナー、OCRシステム」を組み合わせるが、利用者には「登録、印刷、スキャン、確認」の一貫した操作として提供する。
