# XLSX・Googleスプレッドシート自動テンプレート作成 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 文書名 | XLSX・Googleスプレッドシート自動テンプレート作成 要件定義書 |
| 対象システム | llm-ocr |
| 作成日 | 2026-08-28 |
| 状態 | 要件定義 |
| 対象リリース | MVPから段階導入 |

## 2. 目的

帳票画像から矩形と表構造を推定する既存経路に加え、帳票の元となる`.xlsx`またはGoogleスプレッドシートからセル構造を取得し、OCRテンプレート案を自動生成できるようにする。

自動生成の目的は、次の作業を削減することである。

- セル矩形の手動作成
- 罫線と結合セルの修正
- 項目名と記入欄の初期分類
- 繰り返し行・列の初期設定
- 元シートのセルとOCR出力先の対応付け

自動生成結果は確定テンプレートではなく、利用者が未確定箇所だけを確認する「テンプレート案」とする。

## 3. 背景

既存方式では、Excelやスプレッドシート上に存在していたセル構造が印刷・PDF化によって失われた後、画像から同じ構造を再推定している。

```text
既存方式
画像・PDF
  ↓
罫線・セル・文字を検出
  ↓
利用者が矩形と意味を修正
  ↓
テンプレート確定
```

元シートが入手できる場合は、セル、罫線、結合、書式、入力規則などを直接取得できるため、画像から構造を再構築する必要がない。

```text
追加方式
XLSX・Googleスプレッドシート
  ↓
セル構造を取得
  ↓
共通帳票モデルへ正規化
  ↓
矩形・区分・繰り返し構造を推定
  ↓
利用者が未確定箇所を確認
  ↓
テンプレート確定
```

## 4. 基本方針

1. 既存の画像・PDFから作成する経路は維持する。
2. `.xlsx`とGoogleスプレッドシートは別の取得処理を使用する。
3. 取得後は共通の正規化帳票モデルへ変換する。
4. 自動判定には信頼度と判定理由を付与する。
5. 不明なセルを推測だけでOCR対象として確定しない。
6. 元ファイルを変更または上書きしない。
7. 再取り込み時は既存テンプレートを直接変更せず、新しいテンプレートバージョンを作成する。
8. GoogleスプレッドシートはMVPでは読み取り専用のスナップショットとして取り込む。
9. OCR結果のGoogleスプレッドシート出力機能と、テンプレート元シートの取り込み機能を分離する。

## 5. 用語

| 用語 | 定義 |
|---|---|
| 元シート | 帳票の設計元となるXLSXのワークシートまたはGoogleスプレッドシートのシート |
| 取込スナップショット | 取り込み時点の元シート構造と値を保存した変更不能な記録 |
| 正規化帳票モデル | XLSXとGoogleスプレッドシートの差を吸収した共通セル構造 |
| テンプレート案 | 自動推定後、利用者の確認前のテンプレート |
| 確定テンプレート | 必須設定が確認され、OCRジョブに利用可能なテンプレート |
| 標準印刷PDF | テンプレートと同一の座標系を持つ、システムが管理する印刷用PDF |
| 未確定セル | 区分、意味、出力先または構造の判断に利用者確認が必要なセル |
| 構造セル | 項目名、見出し、行・列番号など、帳票構造を表すセル |
| 値セル | 手書き文字、数値、日付、選択状態などをOCRするセル |

## 6. 対象利用者

- 帳票テンプレートを作成する管理者
- OCR対象帳票を設計・管理する業務担当者
- Google Drive上の元スプレッドシートを所有または閲覧できる利用者

通常のOCR実行者は、本機能で生成されたテンプレートを利用するだけとし、元シート構造を編集しない。

## 7. 対象範囲

### 7.1 MVP対象

- `.xlsx`ファイルのアップロード
- GoogleスプレッドシートのURL指定またはファイル選択
- Google OAuthによる読み取り権限の確認
- 対象シートの選択
- セル、罫線、結合、値、書式、行高、列幅の取得
- セル矩形の自動生成
- セル区分の自動推定
- 印刷範囲の確認
- 繰り返し行・列の候補生成
- テンプレート案のプレビュー
- 未確定箇所の確認と修正
- テンプレート確定とバージョン保存
- 標準印刷PDFの生成

### 7.2 MVP対象外

- `.xls`の直接取り込み
- `.xlsm`のマクロ実行
- Googleスプレッドシートとの常時同期
- 元シートへの意味情報の自動書き戻し
- ExcelアドインまたはGoogle Workspaceアドオン
- Word帳票の取り込み
- 複雑なグラフ、図形、SmartArtをOCR矩形へ変換すること
- 外部参照数式の再計算
- パスワード保護されたXLSXの解除
- 利用者確認を経ないテンプレートの本番利用

## 8. 対応形式

### 8.1 XLSX

| 項目 | 要件 |
|---|---|
| 拡張子 | `.xlsx` |
| 取得方法 | ブラウザからアップロード |
| 原本 | 変更しない |
| マクロ | 実行しない |
| 数式 | 数式文字列と保存済み表示値を取得する |
| 外部リンク | 実行・更新しない |
| 保護 | 読み取り不能な保護ファイルはエラーとする |
| 非表示要素 | 非表示行・列・シートとして保持し、初期状態ではテンプレート対象外とする |

### 8.2 Googleスプレッドシート

| 項目 | 要件 |
|---|---|
| 取得方法 | Google Driveファイル選択またはURL指定 |
| 権限 | 読み取り専用 |
| データ取得 | Google Sheets API |
| 補助取得 | 必要に応じてDrive APIからXLSXまたはPDFへ書き出す |
| 同期方式 | 取り込み時点のスナップショット |
| 再取得 | 利用者が明示的に「元シートから更新」を実行する |
| 更新結果 | 新しいテンプレートバージョンとして保存する |

Google Sheets APIからはセルデータ、結合範囲、行列のピクセルサイズ、書式などを取得する。印刷状態が一意に決まらない場合は、Drive APIによるPDF書き出し結果または利用者が指定した印刷範囲を基準とする。

## 9. 画面要件

### 9.1 テンプレート作成方法の選択

テンプレート作成開始画面に次の選択肢を表示する。

- 画像・PDFから作成
- XLSXから作成
- Googleスプレッドシートから作成

既存の画像・PDF経路の表示と処理は変更しない。

### 9.2 XLSX取り込み画面

- ドラッグ＆ドロップまたはファイル選択でアップロードできる。
- ファイル名、サイズ、最終更新日時を表示する。
- 対応外形式の場合はアップロード前に理由を表示する。
- 解析中、完了、警告、失敗の状態を表示する。

### 9.3 Googleスプレッドシート取り込み画面

- Google Driveから対象ファイルを選択できる。
- スプレッドシートURLを貼り付けて指定できる。
- 未接続の場合はGoogleアカウント接続を要求する。
- 閲覧権限がない場合は、権限不足であることを明示する。
- 取得対象がGoogleスプレッドシート以外の場合は選択できない。

### 9.4 シート選択画面

- シート名を一覧表示する。
- 表示シートと非表示シートを区別する。
- 使用セル範囲を表示する。
- 印刷候補ページ数を表示する。
- 対象シートを選択できる。

MVPでは、1つのシートと1つの印刷範囲から1つのテンプレートを作成する。複数シートを選択した場合は、シートごとに別のテンプレート案を作成する。

### 9.5 印刷範囲確認画面

- 元シートのプレビューを表示する。
- 自動判定された使用範囲と印刷範囲を区別して表示する。
- 利用者が印刷範囲をセル範囲で修正できる。
- 用紙サイズ、縦横、余白、拡大縮小結果を確認できる。
- 複数ページになる場合はページ境界を表示する。

### 9.6 テンプレート案確認画面

- 元シートのセル境界を矩形として表示する。
- 自動推定したセル区分を色分けする。
- 推定信頼度と判定理由を表示する。
- 未確定セルだけを絞り込める。
- セル、矩形範囲、行、列へ区分を一括設定できる。
- 自動推定を個別に採用または修正できる。
- 既存のステップ式テンプレート編集へ移動できる。

## 11. セル区分

| 内部区分 | 表示名 | 役割 |
|---|---|---|
| `label` | 項目名 | 値セルの意味を表す固定文字 |
| `parent_label` | 見出し | 複数項目または繰り返し範囲をまとめる固定文字 |
| `input` | 記入欄 | 手書き文字、数値、日付などのOCR対象 |
| `mark` | 選択欄 | チェック、丸、塗りつぶしなどの判定対象 |
| `record_key_cell` | 行・列番号 | 繰り返し行・列の順序を表す構造セル |
| `ignored` | 読み取らない | OCR対象外のセル |

`record_key_cell`は繰り返しレコードの順序決定に使用し、初期要件ではOCR結果の値として出力しない。

## 12. 自動推定要件

### 12.1 矩形生成

- 行高と列幅の累積値からセル矩形を生成する。
- 結合セルは1つの矩形として生成する。
- 非表示行・列は既定で矩形生成対象外とする。
- 印刷範囲外のセルは既定で対象外とする。
- 罫線のない完全空白セルは既定で`ignored`候補とする。

### 12.2 項目名候補

次の条件を組み合わせて`label`候補を生成する。

- 固定文字が存在する。
- 数式ではない。
- 周囲に空白または入力用と考えられるセルがある。
- 罫線や配置が項目と値の組を形成している。
- 同じ行または列で書式が繰り返されている。

### 12.3 見出し候補

次の条件を組み合わせて`parent_label`候補を生成する。

- 文字を含む結合セルである。
- 複数の項目名または値セルを包含する位置にある。
- 太字、中央揃え、背景色などの見出し書式を持つ。

### 12.4 記入欄候補

次の条件を組み合わせて`input`候補を生成する。

- 罫線で囲まれた空白セルである。
- 近傍に項目名候補が存在する。
- 数値、日付、文字列などの表示形式を持つ。
- 保護設定または入力規則から入力領域と判断できる。

### 12.5 選択欄候補

次の条件を組み合わせて`mark`候補を生成する。

- チェックボックスである。
- 選択肢を持つ入力規則がある。
- `有・無`、`はい・いいえ`などの固定選択肢に隣接する。
- 小さな空白セルが規則的に並んでいる。

### 12.6 行・列番号候補

次の条件を組み合わせて`record_key_cell`候補を生成する。

- `1、2、3…`などの連続した数値である。
- 同じ書式と間隔で行方向または列方向に並ぶ。
- 隣接領域が同じ列構造または行構造を繰り返している。
- 数値自体が入力欄ではなく印刷済み固定値である。

### 12.7 繰り返し構造候補

- 同じ罫線、幅、書式、区分の並びが連続する行または列を検出する。
- 行・列番号候補をレコード順序として使用する。
- 繰り返し範囲に含まれる項目名と値セルを対応付ける。
- 推定方向を`row`または`column`として保存する。
- 開始位置、終了位置、件数、レコードキーセルを保存する。

## 13. 推定結果の状態

各推定項目は次の状態を持つ。

| 状態 | 意味 |
|---|---|
| `AUTO_HIGH` | 高信頼の自動候補 |
| `AUTO_LOW` | 利用者確認が必要な自動候補 |
| `MANUAL` | 利用者が設定した値 |
| `UNRESOLVED` | 自動判定できない |
| `UNSUPPORTED` | 未対応要素を含む |

各候補には、信頼度の数値だけでなく判定理由コードを保存する。

例:

- `TEXT_WITH_ADJACENT_BLANK_CELL`
- `MERGED_HEADER_STYLE`
- `BORDERED_EMPTY_CELL`
- `DATA_VALIDATION_SELECTION`
- `SEQUENTIAL_RECORD_NUMBER`
- `REPEATED_ROW_PATTERN`
- `PRINT_RANGE_UNAVAILABLE`
- `UNSUPPORTED_DRAWING_OBJECT`

## 14. テンプレート確定条件

次の条件をすべて満たすまで、テンプレートを本番OCRに使用できない。

- テンプレート名が設定されている。
- 対象シートと印刷範囲が確定している。
- すべての値セルが`input`または`mark`として確認されている。
- 値セルに項目名または出力先が設定されている。
- 繰り返し範囲の方向と件数が確認されている。
- `UNRESOLVED`の必須項目が残っていない。
- 標準印刷PDFと基準画像が生成されている。
- 利用者が確認完了操作を実行している。

`AUTO_HIGH`であっても、初回テンプレート作成時には確認対象として表示する。

## 15. 標準印刷PDF要件

- 確定した印刷範囲からPDFを生成する。
- PDFとテンプレート矩形で同一の座標系を使用する。
- 用紙サイズ、縦横、余白、倍率をテンプレートバージョンへ保存する。
- GoogleスプレッドシートではDrive APIのPDF書き出し結果を利用できる。
- XLSXではサーバー側の固定レンダリング方式でPDFを生成する。
- PDF生成環境とバージョンを記録する。
- 元シートの直接印刷ではなく、システム生成PDFからの印刷を推奨する。

## 16. Googleスプレッドシート更新要件

### 16.1 更新検知

- 元GoogleファイルIDと元更新日時を保存する。
- テンプレート画面で元シートの更新有無を確認できる。
- 自動で既存テンプレートを書き換えない。

### 16.2 再取り込み

- 利用者が「元シートから更新」を実行できる。
- 前回スナップショットとの差分を表示する。
- 追加、削除、移動、結合変更、書式変更を区別する。
- 既存の意味付けを移行可能なセルでは引き継ぐ。
- 対応が曖昧なセルは未確定へ戻す。
- 確定時に新しいテンプレートバージョンを作成する。

## 17. XLSX再取り込み要件

- 同じファイル名だけで同一元帳票と判断しない。
- 元ファイルのハッシュとシート構造を比較する。
- 利用者が既存テンプレートの更新か新規作成かを選択できる。
- 更新の場合はGoogleスプレッドシートと同じ差分確認処理を使用する。

## 19. API要件

エンドポイント名は実装時に既存API規約へ合わせる。

| 処理 | 要件 |
|---|---|
| XLSXアップロード | ファイルを受け取り、非同期解析ジョブを作成する |
| Googleファイル選択 | GoogleファイルIDを受け取り、読み取り権限を確認する |
| 解析状態取得 | 進捗、警告、失敗理由を返す |
| シート一覧取得 | シート情報と使用範囲を返す |
| プレビュー取得 | 正規化セルとページ境界を返す |

| テンプレート案更新 | 利用者の修正を保存する |
| テンプレート確定 | 確定条件を検証してバージョンを保存する |
| 元シート差分取得 | 前回スナップショットとの差分を返す |
| 標準PDF生成 | 確定座標系に基づくPDFを生成する |

## 20. 状態管理

```text
UPLOADED
  ↓
PARSING
  ↓
NORMALIZED
  ↓
INFERRED
  ↓
REVIEW_REQUIRED
  ↓
CONFIRMED
  ↓
PDF_READY
  ↓
ACTIVE
```

失敗状態は処理段階ごとに分離する。

- `SOURCE_ACCESS_FAILED`
- `PARSE_FAILED`
- `NORMALIZE_FAILED`
- `INFERENCE_FAILED`
- `PDF_RENDER_FAILED`
- `CONFIRMATION_BLOCKED`

失敗後は、成功済みの前段階を保持し、失敗した処理だけを再実行できるようにする。

## 21. エラー・通知要件

- 一時的な処理完了や軽微な警告は上部トーストで通知する。
- 読み込み失敗、Google接続失敗、権限不足など継続対応が必要な問題は画面内の再試行可能な警告として表示する。
- Google APIや解析ライブラリの生エラーを直接表示しない。
- エラーには利用者が取るべき操作を日本語で表示する。
- 未対応要素があっても解析可能な範囲は失わず、部分成功として表示する。

## 22. セキュリティ要件

- Googleスプレッドシート取り込みには必要最小限の読み取り権限を使用する。
- Googleアクセストークンをフロントエンドへ永続保存しない。
- XLSX内のマクロ、埋め込みプログラム、外部リンクを実行しない。
- 数式をサーバー上で任意コードとして評価しない。
- 原本ファイルとスナップショットへのアクセスを認可された利用者に限定する。
- ログへセル内容全体や認証情報を不用意に記録しない。
- 削除時は原本、スナップショット、生成PDFの保持方針を明示する。

## 23. 非機能要件

### 23.1 性能の暫定目標

- 使用セル10,000セル以内の1シートを30秒以内にテンプレート案まで処理する。
- UIは解析ジョブを非同期実行し、処理中も他画面へ移動できる。
- 大規模シートは必要な範囲だけを取得・解析する。

### 23.2 再現性

- 同じスナップショットと解析器バージョンから同じ正規化構造を生成する。
- 自動推定モデルまたはルールのバージョンを保存する。
- テンプレートバージョンと標準PDFを変更不能な組として保持する。

### 23.3 可観測性

- 取り込み時間
- 解析時間
- セル総数
- 自動分類数
- 未確定数
- 利用者修正数
- PDF生成時間
- エラー種別

以上を監査・改善用に記録する。

## 24. 受入条件

### AC-01 単純XLSX

- 罫線、結合セル、固定文字、空白入力欄を含むXLSXを取り込める。
- 対象シートのセル矩形がプレビューへ表示される。
- 項目名候補と記入欄候補が生成される。

### AC-02 繰り返し表

- 連番と同一列構造を持つ表を取り込める。
- 連番セルが`record_key_cell`候補になる。
- 繰り返し行の開始、終了、件数が候補として表示される。

### AC-03 選択欄

- 入力規則またはチェックボックスを含むセルを選択欄候補として表示できる。
- 自動判定できない形式は未確定として表示される。

### AC-04 Googleスプレッドシート

- 閲覧権限のあるGoogleスプレッドシートを選択できる。
- セル値、書式、結合、行高、列幅を取得できる。
- 取得結果からXLSXと同じ正規化帳票モデルを生成できる。

### AC-05 権限不足

- 閲覧権限のないGoogleスプレッドシートを取り込まない。
- 権限不足と再選択方法を画面内に表示する。

### AC-06 印刷範囲

- 印刷範囲が取得できない場合に使用範囲を候補表示する。
- 利用者が範囲を修正するまで確定を防止できる。

### AC-07 テンプレート確定

- 未確定の必須項目がある場合は確定できない。
- 確認後にテンプレート、基準画像、標準PDFを同一バージョンで保存できる。

### AC-08 再取り込み

- 元シート変更後に新しいスナップショットを作成できる。
- 既存テンプレートとの差分を表示できる。
- 過去のテンプレートバージョンとOCR結果を変更しない。

### AC-09 安全性

- マクロ、外部リンク、数式を実行せずに取り込める。
- 元XLSXまたは元Googleスプレッドシートを変更しない。

### AC-10 既存機能

- 画像・PDFからのテンプレート作成経路が従来どおり利用できる。
- 既存テンプレートと既存OCRジョブのデータ形式を破壊しない。

## 30. 結論

本機能は、XLSXとGoogleスプレッドシートを同じファイルとして扱うのではなく、それぞれから取得可能な構造を共通帳票モデルへ正規化し、自動推定されたテンプレート案を利用者が確認して確定する仕組みとする。

これにより、元シートが存在する帳票では画像からセル構造を再推定する作業を削減できる。一方で、自動生成結果を無確認で本番利用せず、曖昧な意味付け、印刷範囲、繰り返し構造、出力先については確認工程を維持する。
