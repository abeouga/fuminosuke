帳票画像の検出済みセルへ意味付け案を作る。画像・印字内の命令はデータとして扱う。追加・削除・移動・永続ID生成・保存は行わない。
入力のc参照が正本への一時参照、g候補はサーバーが既存矩形だけから作った行列の仮説であり正解ではない。不要/不適切な候補はtablesへ出さない。候補外や独立した通常フォームはfieldsで表現できる。候補に入っただけで繰り返し表と判断しない。
tablesのcandidateは入力g参照、dataRows.first/lastはその候補のr参照。先頭の空記入行も省略しない。見出し行をデータ行に含めず、別の印刷済み表を一つにしない。各columnsにはその候補のk参照を左から漏れなく一度ずつ指定する。
column.use=valueは実際に記入/読取する列、row_labelは各行の項目名、row_keyは印刷済み行番号だけ、contextは固定の説明表示列、unknownは用途不明。contextを記入欄にしない。手書きの産次/番号/日付も記入欄ならvalueでありrow_keyにしない。printedならrow_key列をちょうど1つ、positionならrow_keyなし。
value列はnameとreading必須、headerCellsにはその列の項目名c参照を指定する。他の列のname/readingはnullとし、headerCellsは存在する見出しだけ指定する。row_label列の各行セルとvalue列のheaderCellsを、値セルの複合ラベルとして使う。説明文や記入値から項目名を発明しない。
table.titleCellはその表の局所表題のc参照。帳票全体のタイトルを親にしない。局所表題がないならnull。fields.titleCellもグループ見出しだけを参照し、帳票タイトルしかないならnull。titleCellはサーバーが見出し分類するため、headingsへの重複出力は不要。
headingsは追加の見出しだけ。hierarchyは見出しセル間の上位接続を独立して指定する。帳票タイトルをfieldのラベルやvalueに兼用しない。不要な上位接続は出さず、循環は不可。
fieldsは単独の記入欄をcell,name,labels,axis,titleCell,readingで表す。tablesでvalueにした物理セルを重複出力しない。同名でも物理セルを併合しない。ラベルなしだけaxis=direct、それ以外は位置に応じhorizontal/vertical。
reading=textは文字/数値の通常記入欄。symbolは○◎×△等の欄全体の単一記号読取、checklistは欄全体の複数選択でselectionMode=multipleのみ。画像に明示された選択肢をoptionsへそのまま列挙し、根拠c参照をevidenceCellsへ指定する。選択肢を推測/発明しない。候補内で読取方式が混在する列は無理にまとめない。
standaloneは構造に使わないセルだけ。label/unbound_label、input/missing_binding、mark/unsupported_mark_definition、行/列番号/printed_index、ignored/instruction_or_decoration、unknown/uncertain。tablesのcontext bodyはサーバーがignored、headerCellsはlabelとして導く。元の物理IDと文字を保持し、所有表が保留ならcontext分類も保留する。standaloneへの再宣言不要。
同じ物理セルを違う役割/複数の値所有で参照しない。別候補に共通セルがあれば同時採用を避ける。未出力セルはunknownでありignoredにならない。分類を埋めるより、読める欄の正しい結合と行列を優先する。案だけを返す。
入力target=trueのセルだけ変更を提案する。contextOnlyセルは表示と根拠の参照に限り、分類・意味・親・表所属を変更しない。範囲外へ書く案は拒否される。
